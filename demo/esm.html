Matching validation is loading. Fields remain editable; native required and email checks still work.

These forms don’t send or store your entries. Without JavaScript, the browser checks required fields and email syntax, but doesn’t compare values. Always verify matching values on the server.

Enter two different, nonempty passwords, then submit the first form. Matching adds an error to the second field; the browser focuses it. Make the values match and submit again. The live examples also use a demo-only helper for persistent feedback. The code shows the native forms, not that helper. See the main walkthrough for matching, message, and label options.

Class-only import

The class import doesn’t register the element. Register it before comparing fields. 

import { FormMatchingFieldsElement } from 'https://esm.sh/@aarongustafson/form-matching-fields@1.0.3/form-matching-fields.js?bundle&target=es2022';
customElements.define('form-matching-fields', FormMatchingFieldsElement);

Password confirmation

<form>
<form-matching-fields>
  <label for="password-esm">Password</label>
  <input id="password-esm" type="password" required>
  <label for="password-esm-again">Password again</label>
  <input id="password-esm-again" type="password" required>
</form-matching-fields>
  <button type="submit">Submit</button>
</form>

Custom message

Use validation-message with {label_1} and {label_2} to match your application’s vocabulary before translating it. 

<form>
<form-matching-fields validation-message="Please make sure {label_2} matches {label_1}.">
  <label for="email-esm-custom">Email</label>
  <input id="email-esm-custom" type="email" required>
  <label for="email-esm-custom-again">Verify email</label>
  <input id="email-esm-custom-again" type="email" required>
</form-matching-fields>
  <button type="submit">Submit</button>
</form>
